# TimeBet 阶段 14：交互式排程

- 状态：完成
- 日期：2026-08-19

## 本阶段交付

1. 本周计划中的未执行时间块可以直接拖到周内另一天。
2. 拖动保留原来的本地开始时间和计划时长，只改变执行日期。
3. 日期卡片在拖动期间显示可放置、时间冲突和当前日期三种即时状态。
4. 前端使用当前周数据预判时间重叠，冲突落点会回弹并保留原计划。
5. 合法落点仍调用既有 `timeblock.move`，由应用层和 SQLite 执行最终重叠与状态校验。
6. 成功拖动或表单调整后显示七秒撤销入口；撤销前会确认时间块没有再次变化。
7. 执行中的时间块不会提供拖拽能力，也不能打开调整表单。
8. 原有调整表单继续保留，作为键盘操作、精确修改和拖拽不可用时的兜底。

## 交互反馈

- 可放置日期使用绿色边框、轻微浮起和明确文案；
- 冲突日期使用红色边框并显示“该时段已有安排”；
- 原日期使用中性色提示，不会产生无意义更新；
- 可拖动卡片显示拖动图标、悬停浮起和抓取光标；
- 移动失败时同时显示就近通知和原有错误信息；
- 系统启用“减少动态效果”后会关闭卡片和落点过渡。

## 数据与协议

本阶段没有新增数据库迁移或桌面消息协议，继续复用：

- `planner.week`
- `timeblock.move`

数据库最新架构版本仍为 6。撤销也是一次经过完整业务校验的 `timeblock.move`，不会绕过冲突规则。
