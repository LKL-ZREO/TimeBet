# TimeBet 阶段 7：星愿机时间挑战

- 状态：完成
- 日期：2026-08-12

## 本阶段交付

1. 时间挑战页实现学习主题的三列星愿机，滚轴只表现后端已确定的结果。
2. 星愿机默认关闭，第一次使用必须明确了解规则并主动开启。
3. 用户可在挑战页或设置页随时关闭，关闭不会删除挑战历史和账本。
4. 单次最低投入 1 分钟，使用整分钟步长，最多为最新余额的 10%，且不超过 30 分钟。
5. 可用余额至少为 10 分钟，每个本地自然日最多完成 3 局。
6. 学习时间块运行或暂停期间均不能挑战。
7. 页面公开每个档位的概率、返还倍数、概率版本和 95.5% 长期平均返还率。
8. 最近挑战显示图案、档位、投入、净变化与发生时间。

## 概率版本

首个版本为 `star-wish-v1`：

| 档位 | 概率 | 返还倍数 |
| --- | ---: | ---: |
| 星光熄灭 | 40% | 0 倍 |
| 留下火种 | 20% | 0.5 倍 |
| 小小幸运 | 25% | 1.5 倍 |
| 双倍进展 | 12% | 3 倍 |
| 星愿降临 | 3% | 4 倍 |

所有概率总和为 100%，加权平均返还为 95.5%。概率表由后端规则对象同时用于结算和前端展示，界面没有独立隐藏权重。

## 原子结算与幂等

每次挑战由前端生成唯一局 ID。SQLite 即时写事务依次执行：

1. 检查该局 ID 是否已经提交；已提交则返回原结果。
2. 检查星愿机是否启用、是否有活动学习会话。
3. 按本地自然日检查今日已完成局数。
4. 重新汇总不可变账本得到最新余额。
5. 校验最低余额、整分钟步长、10% 上限和 30 分钟绝对上限。
6. 根据加密随机值和 `star-wish-v1` 重新解析档位。
7. 追加一条净额 `game-win` 或 `game-loss` 账本。
8. 写入投入、返还、概率版本、原始随机值和账本关联。

账本与挑战局同时提交或同时回滚。桥超时重试会复用同一局 ID，不会重复扣减。

## 消息协议

- `challenge.overview`
- `challenge.settings.update`
- `challenge.play`

挑战结果只由桌面后端生成。网页不能传入随机值、返还倍数或目标结果。

## 数据迁移

迁移 `004_challenge_settings.sql` 新增默认关闭的单例挑战设置和挑战时间索引。已有 `game_rounds` 与追加式账本结构直接复用，旧迁移保持不变。

## 安全边界

- 不涉及真钱、支付、内购、充值或真实商品映射。
- 不提供自动连续挑战、排行榜或好友对战。
- 不使用隐藏概率、“差一点中奖”或强烈失败刺激。
- 减少动态效果系统偏好会缩短滚轴动画。
- 学习计时优先于挑战，活动会话期间挑战由数据库事务再次拒绝。
